TANK ARCADE — 과제 2

실제 입력 표본의 값과 범위를 확인하는 기록입니다. 아래 수치는 본문에 표시된 표본·한계 안에서 해석해야 합니다.

사용자가 제공한 탱크 게임을 개선했습니다. 기본 진입은 SURVIVAL / EASY / ASSAULT입니다. WASD·방향키로 이동하고 Space 입력 하나당 탄환 하나를 발사 대기열에 넣습니다. 발사 간격은 탱크별로 적용됩니다. P 또는 버튼으로 일시정지합니다. 포커스를 잃으면 자동 일시정지하며, 계속하기로 재개합니다.

SURVIVAL은 30초 생존하면 성공, HP 0이면 실패입니다. DUEL은 보스 HP 0이면 성공, 내 HP 0 또는 30초 시간 초과면 실패입니다. 같은 설정으로 다시 시작하면 HP·시간·점수·탄환·입력·효과를 초기화합니다.

실제 난이도 비교

자동 플레이이며 사람의 플레이 기록이 아닙니다. 실제 브라우저의 같은 게임 엔진에서 고정 1/60초 간격으로 실행했습니다. SURVIVAL / NORMAL / ASSAULT, 시드 1001~1010, 3초마다 오른쪽·위·왼쪽·아래로 순환하고 발사 가능한 때에 발사했습니다. 적 이동 기준값 DIFF 하나만 2.0→1.2로 바꿨습니다. 다른 난이도 값은 고정했습니다.

  • 변경 전 10회: 생존 시간 2.250~12.400초, 중앙값 6.775초, 피격 실패 10회.
  • 변경 후 10회: 생존 시간 2.350~10.350초, 중앙값 6.400초, 피격 실패 10회.
  • 선택: 기준값 2.0 유지. 느린 적이 이 조작 방식에서 중앙 생존 시간을 늘리지 않았으므로 1.2 변경을 채택하지 않았습니다. 이 제한된 자동 경로로 사람의 적정 난이도나 성공률을 추정하지 않습니다. 초기 화면은 EASY로 시작하고 다른 난이도는 선택할 수 있습니다.
  • 전체 20회 원본 표: plays.csv. 점수·시간·실패 원인·입력 수·프레임 수를 보존합니다.

입력·상태·저장 검사

실제 브라우저에서 발사 이벤트 10개를 0.5ms에 보냈습니다. 입력 10·대기 10 상태 변화와 이후 발사 10·대기 0을 확인했습니다. 일시정지 중 120개 업데이트 호출에서도 상태가 같았습니다. 성공과 실패 상태를 각각 만든 뒤 재시작해 현재 판 값 초기화를 확인했습니다. 종료 상태 검사에는 의도적으로 마지막 시간·피격 조건을 주입했고 난이도 비교에는 주입하지 않았습니다.

정상 저장값 복원, 빈 문자열, 손상 JSON, 잘못된 객체, null 입력에서 복구를 확인했습니다. 기록 최고값·최근 20회·설정·보스 학습이 보존되며, 손상값은 최고값 0·최근 기록 없음·소리 켜짐·운영체제 움직임 설정을 기본값으로 사용합니다. 브라우저가 저장을 막아도 게임은 계속됩니다. 이전 v4 저장값은 새 v5 공간에 옮기지 않으므로 이전 개인 기록은 변경하지 않습니다.

효과는 발사·명중·피격·파괴·보스 기술·판 종료에서만 생성됩니다. 음소거는 현재 오디오 컨텍스트도 즉시 정지합니다. 움직임 줄이기는 입자와 화면 흔들림을 즉시 지우고 이후 생성을 막습니다. 메뉴와 효과 설정은 키보드로도 실행됩니다.

실제 결함과 수정

  • 연속 발사 입력을 쿨다운 중 버림 → 입력별 대기열 1회 추가·각 탄환 1회 발사.
  • 재시작에 눌린 키와 이전 프레임이 남을 수 있음 → 키·대기열·프레임·효과 초기화.
  • 저장 기록의 난이도가 고정 2.0으로 표시됨 → 실제 선택 레벨과 적 속도를 각각 저장.
  • 위쪽으로 떠난 적 탄환이 제거되지 않음 → 상단 경계를 포함한 화면 밖 탄환 제거.
  • 음소거 뒤 이미 재생 중인 효과가 계속됨 → 오디오 컨텍스트 즉시 정지.
  • 검사 중 window 대상 입력에서 closest 함수 오류 → 요소가 아닌 이벤트 대상도 처리. 수정 후 동일 입력 검사 통과.

공개 안전

계정·서버·분석 추적·외부 폰트·원격 자산 없이 동작합니다. 배포 후보 9개 파일의 비밀값 지정 패턴 검사에서 발견 0건이고 공개 문안에서 개인정보를 발견하지 않았습니다. 지정 패턴 검사가 모든 종류의 비밀값을 증명하는 것은 아닙니다.

PC 경계와 실제 10분 실행

  • 실제 게임 iframe 뷰포트 1366×768과 1920×1080에서 가로 넘침 0px. 시작 버튼·전장·발사 버튼의 경계가 모두 화면 안에 있었습니다. 검사 도구의 바깥 창 크기와 게임 뷰포트 크기를 구분했습니다.
  • 키보드 P로 0.2초에서 일시정지한 뒤 1366×768→1920×1080으로 변경해 HP 3·점수 0·시간 0.2를 유지했습니다. P로 재개하고 Space를 눌러 입력 1·발사 1·대기 0을 확인했습니다. 바깥 검사 버튼으로 포커스를 이동하면 PAUSED가 됐습니다.
  • 새로고침 뒤 최근 기록 20개와 음소거·움직임 감소 설정을 유지했습니다.
  • 실제 벽시계 2026-10-04 03:46:38.353~03:56:38.366 UTC, 600.01초 동안 98판을 연속 실행했습니다. 고정된 자동 입력으로 진행했으며, 끝난 시점 RUNNING·HP 3에서 추가 발사 입력이 정확히 1회 반영됐습니다. 해당 검사 기간에 수집한 콘솔 오류는 0건입니다. 시간 가속을 사용한 20회 비교와 이 실제 10분 검사는 별개입니다.
  • 작은 화면에서 전장 아래 조작 영역이 잘리던 문제를 확인해 전장 높이를 화면 높이에 맞추고 두 기준 화면에서 다시 검사했습니다.

짧은 확인 방법 — 4줄

위치: 공개 게임 주소의 TANK ARCADE 화면으로 갑니다. 행동: ① GAME START 클릭 → ② Space 한 번 → ③ P 한 번을 누릅니다. 통과 모습: 발사 입력 1·발사 1·대기 0이 표시되고 PAUSED에서 시간이 멈춥니다. 안 될 때 모습: 시작이 안 되거나 발사가 누락·중복되거나 PAUSED에서도 시간이 증가합니다.

AI와 본인 판단

AI에게 맡긴 일: UI 개선, 입력·저장 결함 수정, 자동 플레이 비교와 검사 기록 작성. 직접 판단한 일: 원본 탱크 게임을 만들고, 난이도 조절과 고급스러운 UI/UX 개선을 요청했습니다. AI 제안을 따르지 않은 일: 아직 최종 개선안 피드백 전이므로 별도 사례가 없습니다. 난이도 값 선택은 현재 AI의 실험 결과에 따른 제안입니다.
